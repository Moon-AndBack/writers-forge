# 国际化（i18n）

界面文案全部经 i18next 26 + react-i18next 17 从 `t()` 取用，支持 `zh-CN`（默认、key 真源）与 `en` 两档。资源随渲染层打包内联，不发网络请求，也不引入语言检测插件。本文说明资源如何组织、key 如何命名、类型如何校验、新增文案 / 命名空间的完整流程，以及不可越界的不译项。

> 代码是唯一真源。本文论断均带 `文件:行号`；与代码冲突时以代码为准（[`docs/README.md:61`](../README.md)）。

## 1. 资源组织

```text
src/renderer/src/i18n/
  config.ts            # SUPPORTED_LOCALES / DEFAULT_LOCALE / resolveLocale / LOCALE_SETTING_KEY
  index.ts             # i18next 单例初始化（幂等），resources 内联 zh-CN / en
  context.ts           # LocaleContext + useLocale（无 Provider 时容错）
  LocaleProvider.tsx   # 唯一持有当前语言，负责三处同步
  types.d.ts           # CustomTypeOptions 类型增强（仅参与类型检查）
  locales/
    zh-CN/             # key 真源：21 个 ns 文件 + index.ts（core 聚合）+ writerResources.ts（写作域聚合）
    en/                # 同名 21 个 ns 文件 + index.ts / writerResources.ts 聚合（均 satisfies）
```

命名空间（ns）与 `locales/*/index.ts`（core）、`locales/*/writerResources.ts`（写作域）的登记项一一对应，顺序两侧一致（`locales/zh-CN/index.ts:26-39`、`locales/en/index.ts:20-33`，写作域见两侧 `writerResources.ts:22-32` / `19-29`）。下表为 zh-CN 侧叶子 key 数（2026-11-10 实测），en 侧逐 ns 与之一致，两侧各 1300：

## 2. key 命名规范

- **点分路径 `<group>.<leaf>`，全部小写 camelCase**：层级按「功能域 → 区块 → 语义」组织，最多约四层，如 `plot.dialog.deleteLine.message`、`bookshelf.status.todayWords`。
- **key 稳定、语义化**：不随 UI 微调改名。改文案只改值，不改 key；同一含义不要在不同 ns 各写一份（`common.loading`、`chapters.rename` 直接复用，见 `locales/zh-CN/entities.ts:5-6`、`locales/zh-CN/plot.ts:6`）。
- **插值统一 `{{name}}`**：`t('dialog.deleteLine.message', { name })`；多个参数平铺传入，不要在 JSX 里拼接字符串（`locales/zh-CN/plot.ts:19`）。
- **纯计数参数用 `{{n}}`，不要用 `{{count}}`**：`count` 会被 i18next 当作复数选择器，转去查 `_one` / `_other` 变体，而本项目资源没有复数变体（`src/main/database/diagnostics/types.ts:48-49`）。诊断文案的 19 处计数均写作 `{{n}}`（`locales/zh-CN/diagnostics.ts:11`）；`bookshelf.status.*` 为历史写法仍传 `count`，新文案不要沿用。
- **需内联富文本时用 `<Trans>`**：资源写 `<b>{{value}}</b>`，组件侧 `<Trans i18nKey="status.totalWords" ns="bookshelf" values={{ value }} components={{ b: <b /> }} />`（`src/renderer/src/pages/Bookshelf.tsx:355-393`）。禁止在 JSX 里手工拆文案与标签。
- **默认 ns 为 `common`**（`i18n/index.ts:30`）：取 `common` 的 key 时可省略 ns 参数；跨 ns 场景用多次 `useTranslation('a')` / `useTranslation('b')`，不要靠字符串前缀拼接。

一个最小闭环（资源 → 消费）：

```ts
// locales/zh-CN/plot.ts
const plot = {
  newLine: '新建剧情线',
  dialog: {
    deleteLine: {
      title: '删除剧情线',
      message: '确定删除「{{name}}」？该线下的场景节点会一并删除。'
    }
  }
}

// 组件内（同 ns 点分路径，不带 ns 前缀）
const { t } = useTranslation('plot')
t('dialog.deleteLine.message', { name: line.name })
```

## 3. 类型校验机制

- **真源**：`locales/zh-CN/index.ts:48` 导出 `ZhCNResources = typeof zhCN & typeof import('./writerResources').default`，其结构即全部 21 个 ns 的 key 树。
- **类型增强**：`i18n/types.d.ts:7-12` 把 `CustomTypeOptions` 的 `defaultNS` 设为 `'common'`、`resources` 设为 `ZhCNResources`，从而为 `t()` 提供 key 补全与拼写校验；该 `.d.ts` 由 `tsconfig.web.json:2-7` 的 `src/renderer/src/**/*` 覆盖。
- **聚合约束**：`locales/en/index.ts:33` 以 `satisfies ZhCNCoreResources`、`locales/en/writerResources.ts:29` 以 `satisfies ZhCNWriterResources` 分别校验 core 与写作域，21 个 ns 缺 key 会在 `npm run typecheck` 直接报错。
- **逐文件约束**：21 个 en 文件均在文件尾使用 `satisfies ZhCNResources['<ns>']`（`ai`、`bookshelf`、`chapters`、`common`、`diagnostics`、`dossier`、`entities`、`foreshadow`、`inspiration`、`module`、`onedrive`、`outline`、`plot`、`settings`、`status`、`theme`、`timeline`、`titlebar`、`typography`、`welcome`、`writer`）；它把校验前移到单文件，报错定位更准，多出的 key 也会被对象字面量检查拦下。新增 / 改动 en 文件时必须同步补齐逐文件 `satisfies`。
- **运行期兜底不等于校验**：`returnNull: false` 与 `fallbackLng: 'zh-CN'`（`i18n/index.ts:29,32`）会让缺失 key 回落中文或直接显示 key 本身，不会抛异常，因此 key 的正确性必须靠静态检查保证。

聚合与逐文件约束的配合（现有 21 个 ns 的写法）：

```ts
// locales/en/index.ts:20-33 · core 约束：12 个 ns 缺 key 必报
const en = { ai, /* …其余 11 个 core ns */ welcome } satisfies ZhCNCoreResources

// locales/en/plot.ts · 逐文件加固，现有 21 个 ns 采用
const plot = {/* …与 zh-CN 逐条对齐… */} satisfies ZhCNResources['plot']
```

结论：**新增 en 文件应同时满足两层**——聚合层保证整树不缺 key，逐文件 `satisfies` 让多 key 与定位错误在单文件内暴露；改动既有文件时至少保证聚合层通过，并顺手补齐缺失的逐文件约束。

## 4. 新增命名空间的完整流程

1. **zh-CN 建文件** `locales/zh-CN/<ns>.ts`：文件头注释写明该 ns 的消费方、取用约定与不译边界，`const <ns> = { ... }`，`export default`。
2. **en 建同名文件** `locales/en/<ns>.ts`：头部注释保留「机翻占位 · 待校」并注明以 zh-CN 为准，尾部 `} satisfies ZhCNResources['<ns>']`，key 与 zh-CN 逐条对齐。
3. **两侧聚合文件登记**：按字母序 `import` 并把变量放进聚合对象（core 进 `index.ts`，写作域进 `writerResources.ts`），两侧条目顺序保持一致（`locales/zh-CN/index.ts:26-39`、`locales/en/index.ts:20-33`；写作域见两侧 `writerResources.ts:22-32` / `19-29`）。zh-CN 侧无需改类型导出，`ZhCNResources` 会自动带上新 ns。
4. **组件取用**：`const { t } = useTranslation('<ns>')`，再以同 ns 点分路径 `t('<group>.<leaf>')`；富文本用 `<Trans ns="<ns>" i18nKey="..." />`。
5. **验证**：`npm run typecheck`（key 全等）、`npm run lint`、`npm run build`。不得只加一侧，也不得先合并中文再补英文。

落地样例（新 ns 记作 `<ns>`）：

```ts
// 1) locales/zh-CN/<ns>.ts（真源）
/** <功能域>命名空间：<消费方> 的 <文案范围>。 */
const ns = { panel: { title: '面板标题' } }
export default ns

// 2) locales/en/<ns>.ts（同名、同 key）
/**
 * 机翻占位 · 待校
 * 本文件英文译文由机器翻译生成，尚未人工校对；如见生硬 / 歧义，以 zh-CN 为准。
 */
import type { ZhCNResources } from '../zh-CN'

const ns = { panel: { title: 'Panel title' } } satisfies ZhCNResources['<ns>']
export default ns

// 3) 两侧对应聚合文件各加 import + 聚合项（core → index.ts，写作域 → writerResources.ts，顺序保持一致）
import ns from './<ns>'
```

## 5. 双语同步义务

- **en 文件头固定标注**：每个 `locales/en/*.ts` 开头保留「机翻占位 · 待校」，并说明歧义以 zh-CN 为准（当前 21/21 均已具备，样例见 `locales/en/plot.ts:1-4`）。
- **key 全等**：zh-CN 与 en 各 1300 个叶子 key、21 个 ns，实测无缺无多；新增 key 必须同批补齐另一侧。
- **不得跳译**：不接受「先留中文占位」「只加 zh 等以后补」；en 值可以机翻，但必须存在且语义对应。
- **空串须有意为之并注释**：`plot.timeYearUnit` 英文留空串（英文年份无量词后缀，`locales/en/plot.ts:109`），属既定设计而非漏译；除此之外不得用空串规避翻译。
- **语言自称保留原文**：`zh-CN` 选项在两种语言下都显示「简体中文」，`en` 显示 `English`（`locales/en/settings.ts:4,16`）。
- **标点跟随目标语言**：中文用「」，英文用弯引号 “ ” 与半角标点，避免中英混排；数值、单位与占位符位置按语言习惯调整。

## 6. 语言切换与持久化

**启动**（`src/renderer/src/main.tsx`）：先以 `resolveLocale(navigator.language)` 取系统语言（`:30`），再读 `settings.get('locale')` 覆盖（`:34-45`），随后 `initI18n(initialLocale)` 同步初始化（`:51`），最后挂载 `I18nextProvider` + `LocaleProvider`（`:56-57`）。资源已内联，首帧即为目标语言，无闪文案。

```text
navigator.language ──resolveLocale──┐
                                    ├──> initialLocale ──initI18n()──> 首帧渲染
settings.get('locale') ──有值则覆盖──┘         │
                                              └──> <LocaleProvider initialLocale>
```

**切换**（`LocaleProvider.tsx:30-34`）必须三处同步：

1. React 状态 `setLocaleState`；
2. `i18n.changeLanguage(next)`；
3. `window.api?.settings.set('locale', next)` 持久化（无 API 时静默跳过，界面切换仍生效）。

**语言真源**为 settings 表 `locale` 键（`config.ts:9`），`zh-CN` / `en` 是唯一档位（`config.ts:12-17`）；`resolveLocale` 仅把 `en*` 归为 `en`，其余（含非法值、空串）一律回退 `zh-CN`（`config.ts:24-26`）。不引入 `i18next-browser-languagedetector`（`i18n/index.ts:9-10`）。

**首帧 `<html lang>`**：`index.html:2` 静态写 `lang="zh-CN"`，运行期由 `LocaleProvider.tsx:26-28` 的 `useEffect` 校正为实际语言；新增页面不得自行改写 `document.documentElement.lang`。

**消费方式**：界面语言由 `useLocale()` 读取（`context.ts:17-22`，无 Provider 时回退 `zh-CN` + 空操作），设置页下拉即调用 `setLocale`（`pages/settings/GeneralSection.tsx:38,46-56`）；不要另建语言状态或直读 `locale` 键。

## 7. 不译项与二期边界

**不译项**（保持原文，不得拆进 i18n 资源）：

| 项                     | 说明                                                                              |
| ---------------------- | --------------------------------------------------------------------------------- |
| 品牌 `Writer's Forge`  | 标题栏品牌区、`index.html` 文档标题、窗口标题等品牌标识                           |
| 用户 / 演示数据        | 书稿正文、示例卷章名、笔名等用户内容                                              |
| 分类名称               | 来自 `categories.name`（官方种子数据常量），不进 i18n；旧版自定义分类名为用户数据 |
| `COVER_COLORS[].label` | 封面色名为设计常量，与主进程镜像同步                                              |
| 语言自称               | 「简体中文」/ `English` 始终显示本语言写法                                        |

**已不属不译项**：关系语义码（`superior` / `subordinate` / `peer` / `belongs_to`）的展示名已改由 `dossier` ns 提供——类型名取 `detail.relation.typeName.*`，胶囊的「对端身份标签」取 `detail.relation.peerLabel.out|in.*`（渲染层唯一入口 `pages/writer/dossier/useRelationLabels.ts`；`peer` / `belongs_to` 不建这些 key，胶囊不加前缀、只显示对端名）。`world_semantic_codes.note` 只剩「未知 / 自定义码兜底」用途，仍为中文数据常量、不进 i18n。

**二期边界**（本期已知技术债，不顺手改动）：

- 章 / 卷中文数字编号（「第X章」「卷X」）；
- 相对时间（「刚刚 / N 分钟前 / N 小时前 / N 天前」）；
- 主进程日志、OneDrive 英文 message 与种子数据（教学书、实体种子）保持中文原文；
- 主进程只返回结构化 `code` 或空串默认值，用户可见文案一律由渲染层按 code 映射（`src/main/onedrive/types.ts:5`、`src/main/database/plotShared.ts:18`）。

**判定口径**（拿不准某段文本是否该译时）：

1. 用户能在界面上看到或读屏听到 → 必须译，含 `aria-label`、`title`、`tooltip`、toast、确认框。
2. 落库的数据（书名、卷章名、实体名、正文）→ 不译，属用户内容；展示层只对**默认值**（空名、未命名）用 i18n 兜底（`plot.unnamedLine`、`timeline.defaultName`）。
3. 诊断 / 备份的中间载荷 → 不译，主进程传 `code` + 语言中立参数，渲染层拼句。
4. 设计常量（分类、封面色、主题 id）→ 不译；若将来要译，须主进程与渲染层同步改，不能只改一侧。关系语义码展示名是**已完成迁移的例外**：四个内置码走 i18n，仅 `world_semantic_codes.note` 保留中文原文作未知码兜底。

## 8. 常见错误

| 错误                                                                | 后果                                            | 正确做法                                       |
| ------------------------------------------------------------------- | ----------------------------------------------- | ---------------------------------------------- |
| 只加 zh-CN 或只加 en                                                | `satisfies` 在 typecheck 报缺 key；资源结构失衡 | 两侧同名文件同批创建并登记                     |
| 硬编码中文（按钮 / `title` / `aria-label` / `placeholder` / toast） | 切到 en 仍显示中文，违反 `AGENTS.md` §10        | 一律经 `t()` 取用，含无可见文本的可访问属性    |
| 在 JSX 里拼文案与标签                                               | 语序、标点无法翻译，翻译者拿不到完整句子        | 整句进资源，`<Trans>` + `components` 渲染      |
| 在主进程 / preload 里调用渲染层 `t()`                               | 主进程无 React 与资源，构建或运行即失败         | 主进程返回 `code` / 空串，渲染层映射文案       |
| 用 ns 字符串前缀拼接 key                                            | 缺类型补全，改名后静默失效                      | 多次 `useTranslation` 分别取用                 |
| 计数参数写 `{{count}}`                                              | 触发复数后缀查找，取不到 `_one` / `_other`      | 纯计数用 `{{n}}`                               |
| 新增 ns 忘登记任一侧 `index.ts`                                     | 资源不加载或类型不含该 ns                       | 两侧聚合对象同时登记，顺序一致                 |
| 改中文不改英文                                                      | 两语言语义漂移，key 虽全等但内容过期            | 同一提交内同步 en，保留「机翻占位 · 待校」标注 |
